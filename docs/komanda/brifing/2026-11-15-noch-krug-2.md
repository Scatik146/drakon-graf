**1. Генератор «код → блок-схема» через ast/acorn — верно, инструменты есть; «код → ДРАКОН-иконы» готового нет — пишете сами.**
- Python: модуль `ast` — стандарт CPython. Готовые код→блок-схема: **pyflowchart** (https://pypi.org/project/pyflowchart), **code2flow** (https://code2flow.com, Python+JS). JS: парсер **acorn** (https://www.npmjs.com/package/acorn); готовое **js2flowchart** (https://bogdan-lyashenko.github.io/js-code-to-svg-flowchart).
- Готового «код → ДРАКОН» **не нашёл**. Существующие ДРАКОН-инструменты идут в **обратную** сторону — диаграмма → код: DRAKON Editor (https://drakon-editor.sourceforge.net/generation.html, генерирует C/C++/Java/C#/Python/Tcl) и DrakonTech (stepan-mitkin/drakon.tech.desktop). Так что маппинг AST → иконы ДРАКОН — ваша собственная работа поверх ast/acorn. Реально, но не «берём готовое».
- **Где сломается**: исключения (try/except — нелокальный переход), async/await и генераторы, рекурсия между функциями, замыкания и функции высшего порядка, динамический вызов (`getattr`, таблицы диспетчеризации, `addEventListener`/колбэки — а ваши HTML/JS-уроки событийные), декораторы/метапрограммирование. `ast` даёт синтаксис, а не межпроцедурный поток управления. Для «фортовских» маленьких функций с простыми ветками/циклами — работает; для остального — теряет.

**2. Prolog-правило как ДРАКОН-схема — частично честно; теряется существенное.**
- Плоские конъюнктивные правила `A :- B, C` как «вопросы подряд Да/Нет» — честно. Несколько правил одного имени как ветки силуэта — честно. «Найти такого Б» как цикл «Для каждого» — приблизительно честно.
- **Что теряется**: **рекурсия** — ваш же пример «А предок В, если А родитель Б и Б предок В» рекурсивен (предок вызывает предок), а силуэт/ветки не выражают самовызов; **откат (backtracking)** — «попробовать следующее правило/решение при провале» не виден на статической схеме; **несколько ответов** — «запоминатели» показывают множество, но не механизм порождения; **унификация** — сопоставление с образцом прячется за «вопросами». Рекурсивное определение предка — канонический контрпример: его схема либо ошибочна, либо требует отдельной иконы вызова + цикла по уровню.

**3. Запрет cut/assert/retract школьные задачи НЕ ломает — верно, с одной оговоркой.**
- **Родословная**: чистые факты + рекурсивные правила, без cut/assert — работает.
- **Классификация животных**: классический «эксперт» берёт cut для детерминизма/эффективности, но без cut корректность сохраняется (возможны дублирующиеся ответы); лечится взаимно-исключающими правилами и `\+`.
- **«Кто где живёт», логические головоломки**: это constraint satisfaction, решается чистым перебором; assert/retract для сбора решений заменяется встроенными `findall/bagof/setof` (не запрещены).
- **Оговорка (вы её не учли)**: в ISO Prolog (стандарт **ISO/IEC 13211-1**) конструкция `(Условие -> Тогда ; Иначе)` — это commit, «мягкий cut», а `\+` (negation-as-failure) реализован через cut-fail. Если запрет — буквально только на `!`, то `->` и `\+` остаются легальны и их достаточно. Если по духу — «никаких commit-операторов», — добавьте `->` в список и **явно разрешите** `\+` и `findall`, иначе учителя запутаются.

**4. Где «всё описывать схемами» станет бюрократией — что вычеркнуть.**
- Схема для *каждой* новой главной функции до кода — вычеркнуть; введите порог (>3 веток или >1 экрана). «Для важного» уже заявлено — нужен критерий.
- ДРАКОН-ГРАФ для *каждой* структуры данных (словарь/список) — вычеркнуть; только сквозные доменные модели.
- Двойной источник правды (генератор + файл с правками) + сканер «схема генератора = схема в файле» — вычеркнуть **строгое равенство**; замените предупреждением о расхождении, иначе сканер вечно ругается на функции, где генератор несовершенен (см. п.1).
- Живые ручные спеки-схемы — вычеркнуть; регенерация по запросу. Схемы для тестов/glue/конфигов — вычеркнуть.
- Оставить: силуэт «алгоритм работы команды» (~10 этапов) и схему сборки урока — высокоценно.

**5. Чего вы не видите.**
- **Дрифт**: вручную правленые схемы гниют относительно кода; сканер либо воет волком (ложные расхождения на async/исключениях), либо его игнорируют.
- **Слепые зоны генератора** (async, события, рекурсия, динамический вызов) упирают правило «схема для каждой главной функции» в стену на ваших же событийных HTML/JS-уроках.
- **«Модель делает черновик, учитель правит»** — черновик может быть уверенно неверным; учитель обязан сверять с реальным кодом, а не наводить красоту. Риск карго-культ-схем.
- **Рекурсия в Prolog** не рисуется как нерекурсивный силуэт (см. п.2).
- **Читаемость для 2–4 классов не проверена**: «связь Иван -> Пётр: родитель» — для второклассника направление неоднозначно (кто чей родитель?). Нужна конвенция + реальные тесты с детьми и с учителем литературы/физкультуры. «Одинаково читают 2–4 и 10–11» — гипотеза, не факт.
- **Сами conventions ДРАКОН** (шампур, силуэт, иконы) — кривая обучения для не-ИТ-учителя, т.е. для вашей же аудитории.
- **Closed-world в Prolog**: «не выводится = ложно» — скрытая семантика; для школьных задач вводит в заблуждение, если не проговорить.
- **Тактильные/оценочные знания** (ваш же п.1а): какой пример дать первым, тон, мотивация — осознанно вне схем; зафиксируйте как out-of-scope, чтобы не схемить педагогику.

- «Ручные схемы кода не храним — генерируем заново»: тогда где живёт правка учителя? Если схему всегда перегенерируют, правки умрут при первом же запуске генератора. Надо решить честно: схема — витрина кода (правки запрещены), или правка схемы — сигнал поправить код. Третьего не дано, а у Claude сейчас ровно посередине.
- Зануде — одно возражение: его список «где сломается генератор» верный, но неполный. Генератор может нарисовать технически верную схему, которую ребёнок не поймёт. Мерило проекта — не «схема совпала с кодом», а «схему прочитал второклассник».

## 2. Prolog и фортификация: шаг или блажь

**По-фортовски — не блажь.** Это не новый курс, а продолжение уже принятого: «каждая функция — одна схема». Маленькие функции и до этого были целью, теперь они правило. Риск только один — время, и он снят «переводим, когда трогаем». Моё слово: продолжать.

**Prolog — даёт, но ограничить.**
- Даёт: ребёнок думает «что верно», а не «что нажимать по шагам». Для родословных и классификаций это не игрушка, а прямо школьное мышление: задал вопрос — получил ответ из правил, а не из ответа учителя.
- Рискует: новый язык посреди года — груз на учителе прежде всего. И есть ловушка, о которой ни Зануда, ни Claude не сказали прямо: ребёнок напишет правило без базового случая («предок — это предок предка») — и запрос повиснет в бесконечной рекурсии. Без предохранителя (лимит глубины с простым сообщением «пошли по кругу — проверь правило») это самый вероятный первый провал режима знаний.
- Моё предложение: Prolog живёт только внутри «режима знаний» готовых уроков, не становится темой в расписании. Фортификация продолжается.

**Признак, что ошиблись:** не дата («до конца четверти» — условность), а два честных счётчика. Первый: дети после 1–2 уроков с «кто -> ?» не отвечают на вопросы по графу без помощи. Второй: учитель тратит на поддержку режима больше минут, чем даёт уроку. Если хоть одно из двух — заморозить без сожалений.

## 3. Как проверить понятность за один урок

Годится не «опрос», а три маленьких дела на реальном уроке:
- **Пройти дорожку вслух.** Дать схему с двумя вопросами Да/Нет и попросить второклассника проговорить путь до конца. Застрял — где именно: на слове, на стрелке, на шаге. Это диагностичнее любой анкеты.
- **Найти перепутанное.** Показать граф, где одна стрелка перевёрнута («Пётр -> Иван: родитель»). Заметил ли — вот и проверка и конвенции, и направления. Если заметил — конвенция работает.
- **Нарисовать свой факт.** Попросить самого нарисовать одну связь про себя или героя книги. Куда поставил стрелку — туда и есть интуитивное чтение.

Пять-шесть детей и пол-урока хватает: считайте не мнения, а застревания. И проверяйте за один день на разных классах — тогда сравнение «2–4 против 10–11» будет честным, а не воспоминанием.

## ЗАНУДА — что в заключении Claude неверно или выдумано

**З1. «Мерило в цифрах: ≤6 шагов на экране, ≤4 связей на узел» — не выдумка, но и не факт.** Это округлённые числа из ответа Алисы (5–6 шагов, 3–4 связи), поданные как метрика. Эмпирики нет. Верно как гипотеза для теста, **неверно как критерий** — пометьте «предположение, проверить на детях».

**З2. «DrakonShema» — это не существующий формат, а ваше имя.** Claude подаёт его как «короткий формат DrakonShema» — звучит как взятый готовый. На самом деле это предлагается определить вам. Не ошибка, но формулировка вводит в заблуждение: назовите «свой промежуточный формат».

**З3. Икона «Вставка» для рекурсии — икона реальна, применение наполовину честно.** «Вставка» (вызов подалгоритма) входит в базовый набор икон ДРАКОН по Паронджанову (текст книги: http://drakon.pbworks.com/w/page/18205498/). Верно, что рекурсивный вызов = Вставка. **Но:** Вставка обратно в тот же силуэт делает схему циклической, а шампур ДРАКОНа рассчитан на одну главную вертикаль без петель. Для одного самовызова — нарисовать можно; для глубокого/общего случая — схема теряет «шампурность». Claude этого не сказал.

**З4. Запрет `->` и разрешение `\+`, findall — верны и согласованы с ISO Prolog.** `findall/3`, `bagof/3`, `setof/3` — стандартные метапредикаты ISO/IEC 13211-1 (https://swi-prolog.discourse.group/t/findall-3-in-place-of-bagof-3-or-setof-3-a-subtle-bug/6421). **Упущено различие, важное для UX «запоминателей»:** `findall` при отсутствии решений возвращает `[]`, а `bagof`/`setof` — *падают (fail)*. Для карточек «кто -> ?» нужен именно `findall` (пустой список = «никого»). Claude разрешил все три, не выбрав — зафиксируйте `findall` как основной.

**З5. Левая рекурсия — главное упущение.** Claude разбирает рекурсию как «Вставка», но не касается *терминации*. Классический канонический пример `предок(A,C):-предок(A,D),родитель(D,C)` уходит в бесконечный цикл (left recursion) — подтверждено: https://stackoverflow.com/questions/64048419/how-to-express-ancestor-recursively . Правило: **нерекурсивное предложение первым, рекурсивный вызов не крайний слева.** Для школьников это ловушка номер один — обязано быть в `KOD-PO-GRAFOVSKI.md`.

**З6. Стоп-проверка Prolog — хорошая, но не операциональна.** «Если до конца четверти не прошёл — заморозить» — нет даты и нет определения «прошёл». Дайте: дату (конец четверти = ?) и критерий «прошёл» = (а) урок проведён в режиме знаний, (б) дети решили ≥1 задачу, (в) учитель не откатился на чистый JS.

**З7. Выдумок ссылок нет.** Все ссылки Claude (Wirth, Полани, Паронджанов, pyflowchart, code2flow, js2flowchart, acorn, DRAKON Editor, DrakonTech) — проверены в круге 1, реальные.

**З8 (упущенное).** Не сказано про `\+` на негрунтованных целях (`\+ X` с не связанной X небезопасно) — для школьных грунтовых фактов не страшно, но в правила надо одной строкой.

## СПЕЦ ПО FORTH

**F1. Дух передаётся верно.** «Словарь маленьких слов, факторизация, слои снизу вверх, однострочный комментарий-слово» — это и есть Forth по Броди: Leo Brodie, *Thinking Forth* (https://thinking-forth.sourceforge.net, PDF: https://www.forth.com/wp-content/uploads/2018/11/thinking-forth-color.pdf) и *Starting Forth*. Правило «каждая функция = одна ДРАКОН-схема» — прямое продолжение фортовского «каждое слово имеет имя и входит в словарь». **Верно, не блажь.**

**F2. Что стоит взять ещё.** (а) Имена слов-функций как «глагол + объект», читаемые в стеке; (б) принцип «факторизуй, пока не станет скучно» — но это вы уже неявно имеете в пороге «>3 веток»; (в)(layering) чередовать «новое слово поверх уже определённых», не прыгая через слой.

**F3. Что не переносится на JS/Python.** Стек данных и постфикс — брать не надо (в JS/Python это анти-идиома, убьёт читаемость, ради которой всё затевалось). Ручное управление стеком возвратов — не нужно. Компиляция слов «на лету» (Forth self-compiles) — в учебном JS бессмысленно. **Берите философию, не синтаксис.**

**F4. Карго-культ — реальный риск, но не здесь.** Карго-культ был бы, если бы вы копировали *форму* Forth (стек, `: слово ;`). Вы копируете *дисциплину* (маленькие функции, слои). Норма. **Риск переносится на другое:** слепая вера, что «функция ≤15 строк = автоматически понятная». Длина ≠ понятность. ДРАКОН-схема — вот проверка, не число строк.

**В3.** Форотификация — **продолжать**, она дешёвая (правило стиля, не переписывание всего) и служит вашей же цели «функция = схема». Старый код «только когда трогаешь» — правильно, снимает главный риск. **Ошиблись, если:** начнёте массово переписывать рабочий старый код ради «фортовской чистоты» в ущерб урокам — это и есть карго-культ.

## СПЕЦ ПО PROLOG

**P1. «Режим знаний» и «по-графовски» — честны.** Факт = подписанная связь, правило = путь по стрелкам со схемой проверки, запрос = пустой «запоминатель», ответ = заполненные — это аккуратная визуальная проекция хорновской логики. ДРАКОН-ГРАФ ловит *декларативный* смысл; ДРАКОН-схема правила ловит *процедурную* проверку. Честно, пока правила плоские (≤3 условий — ваше правило).

**P2. Поправки Claude — верны с двумя уточнениями.**
- Вставка для рекурсии: верно по иконе (З3), но добавьте правило терминации (З5) — без него дети получат зависший swipl.
- Запрет `!` и `->`, разрешение `\+` и `findall`: верно. Зафиксируйте `findall` как основной для карточек (З4). `\+` — только на грунтованных целях (З8).

**P3. Важно для школьников (добавить в KOD-PO-GRAFOVSKI.md).**
- **Порядок правил = порядок попыток.** Prolog пробует сверху вниз; первое подошедшее — «ответ». Дети думают «правила = множество», а тут порядок существенен. Показать на примере: «большая собака» vs «щенок» — порядок меняет вывод.
- **Бесконечная рекурсия (left recursion).** Нерекурсивное предложение первым, рекурсивный вызов не крайний слева (https://stackoverflow.com/questions/64048419).
- **Закрытый мир.** «Не вывели = нет». Claude верно велел проговаривать; добавьте пример-ловушку: «мы не занесли страуса → `\+ может_летать(страус)` истинно, хотя страус не потому, что не летает, а потому, что нет факта».
- **Несколько ответов.** Backtracking даёт их по одному; `findall` собирает. На схеме это не видно — отдельно проговаривать.

**P4. swipl-wasm vs Tau Prolog — для уроков без интернета.** Оба реальные. swipl-wasm: SWI-Prolog, собран Emscripten, бежит целиком в браузере, без сервера (https://www.swi-prolog.org/build/WebAssembly.md, https://swi-prolog.discourse.group/t/wasm-vs-swish-and-others/8840). **Точный размер не знаю — надо измерить** (распространение = 3 файла: ядро .wasm + .js + данные; грузится всё клиентски). Tau Prolog: интерпретатор на чистом JS, цель — ISO Prolog, есть модули для DOM/событий (http://tau-prolog.org, статья Riaza Valverde 2023 — https://www.researchgate.net/publication/373332846). **Для оффлайн-уроков:** Tau Prolog, скорее всего, меньше и проще грузится (один JS-бандл, без .wasm-рантайма), но **подмножество ISO слабее, чем у SWI**. Решайте по двум числам: размер бандла и покрытие нужных вам предикатов — измерьте оба на реальной «Родословной».

**В3.** Prolog — **ограничить до статуса эксперимента** (Claude уже так), **не откладывать, но и не расширять**. Даёт: честную логику для знаний, отдельный «режим знаний» не лезет в ядро. Риск: новый язык посреди года, кривая обучения, подводные камни (P3). **Признак ошибки:** до конца четверти ни один урок не прошёл в режиме знаний от начала до конца с решённой детьми задачей — **заморозить, не закапывать**.

## СПЕЦ ПО JS

**J1. Ядро на JS + Prolog внутри через JSON — разумно.** JS остаётся рантаймом уроков (DOM, события, оффлайн); Prolog — изолированный «движок знаний», связь через JSON — чистый интерфейс, можно менять реализацию Prolog (swipl-wasm ↔ Tau Prolog) не трогая ядро. **Верно.** Риск один: синхронный вызов Prolog из обработчика может блокировать UI — держите вызов в Web Worker или с разбиением по `requestAnimationFrame`.

**J2. «По-фортовски» на событийный JS ложится с натяжкой — там, где есть «главный путь».** Чистые функции-преобразователи (сборка урока, парсинг ГРАФ-текста, расчёты) — ложатся отлично. **Не ложатся:** обработчики `addEventListener` (нет «один вход-один выход», вход = событие), async/await (управление у рантайма), колбэки/Promise, рекурсия DOM-обхода. Для них ДРАКОН-схема = «по запросу, руками», не через генератор. Это согласуется с вашим «события, async — вне генератора».

**J3. Генератор JS→ДРАКОН на acorn — реален на ограниченном подмножестве.** acorn (https://www.npmjs.com/package/acorn) даёт AST; существующий `js2flowchart` (https://bogdan-lyashenko.github.io/js-code-to-svg-flowchart) доказывает, что путь работает. **Граница:** стрелочные функции как обработчики, замыкания, async, генераторы, динамический `obj[methodName]()`, цепочки Promise — генератор теряет или рисует шум. **Решение:** генератор работает только для функций, помеченных «фортовскими» (без async/handler), остальные — вручную.

**J4. Оффлайн: swipl-wasm размер/загрузка.** Конкретный размер не подтверждён (P4) — **измерьте**: `du -h` бандла + время старта на слабом устройстве без сети. Если бандл тяжёлый — preload-кэш через Service Worker (но SW сам требует HTTPS/первого захода онлайн; на GitHub Pages работает, но первый заход должен быть онлайн — это противоречит «работает без интернета с первого раза»). **Альтернатива:** Tau Prolog (один JS-файл, J/P4) — для «с первого раза оффлайн» может оказаться практичнее. Замерьте оба.

**В3.** Как JS-спец: **продолжать, но с двумя ограничителями.** (1) Prolog-движок — за Web Worker, ядро урока на него не зависит: если Prolog не загрузился, урок без «режима знаний» всё равно работает. (2) Генератор схем — только для фортовского подмножества, остальное вручную. **Признак ошибки:** ради Prolog/генератора начали менять структуру рабочих уроков, или урок перестал открываться оффлайн «с флешки» без первого захода в сеть — тогда откатить изоляцию.
