## 0. Как читать этот документ

ГРАФ описан в три слоя, по образцу формального описания ДРАКОНа у В. Д. Паронджанова («Учись писать, читать и понимать алгоритмы», гл. 33–34):

| Слой | Что описывает | Кому нужен в первую очередь |
|---|---|---|
| **1. Лексика** (раздел 2) | из каких знаков состоит текст: строки, отступы, ключевые слова, экранирование | всем; общий для всех наших блоков (`конспект`, `дракон`, `мат`) |
| **2. Текстовый синтаксис** (разделы 3–5) | какие строки бывают и как из строк строится дерево конспекта | разработчику (грамматика), учителю (примеры) |
| **3. Визуальный синтаксис** (разделы 6–8) | какие фигуры получаются, в какие схемы складываются, по каким правилам раскладываются | разработчику движка, дизайнеру |

Связь слоёв: каждая строка текста — это одна операция над заготовкой схемы (раздел 8, таблица «строка → операция»). Кто знает эту таблицу, знает весь язык.

**Каждое правило записано в три части:**
- **Формально** — грамматика, таблица или точный алгоритм. Читает программист;
- **Простыми словами** — одна-две фразы. Читает учитель;
- **Пример** — текст конспекта (и, где важно, что получится).

Слова «должен», «нельзя» относятся к движку. Для учителя в языке нет ошибок — есть **подсказки** (раздел 9): любой текст рисуется, а неудачное место отмечается подсказкой.

## 1. Назначение и принципы

**ГРАФ** — язык для записи **декларативного знания**: определений, правил, свойств, классификаций, сравнений, формул и их разбора. Учитель или ученик пишет обычный текст по нескольким простым правилам, а программа сама строит графический конспект по Паронджанову.

Пара языков в «Живом учебнике»:
- **ГРАФ** — *что знать*: понятия, связи понятий, структура данных;
- **ДРАКОН** — *как действовать*: алгоритмы и процессы.

Расширенная версия объединяет три языка Паронджанова — ГРАФ (схемы конспектов), ГНОМ (запоминатели) и МОЛНИЮ (грамматический разбор) — в один и добавляет к 14 схемам Паронджанова три новые: **Дерево**, **Сцену** и **Шеренгу**.

**Принципы:**

| № | Принцип | Как выполняется |
|---|---|---|
| П1 | Сначала текст, форма выводится | Учитель не рисует; схема строится из текста. Синтаксически неверную схему построить нельзя: любой текст даёт правильно построенный рисунок, нарушения превращаются в подсказки |
| П2 | Жёлтое — запомни, белое — разберись | Жёлтые фигуры — то, что выучивают; белые рамки — примеры и разборы |
| П3 | Одна мысль — одна зона | Зоны `---`, мягкие пределы 7 ± 2, подсказки о длинных фразах |
| П4 | Чем правее, тем хуже (как в ДРАКОНе) | Второстепенное уходит вправо и вниз; если пересечения можно избежать, перенеся элемент на другую сторону, он переносится; лишний уровень не создаётся |
| П5 | Как в Python | Отступы задают вложенность; ключевые слова только строчные; Tab вставляет пробелы |
| П6 | Подсказки вместо ошибок | Во всех модулях программы |
| П7 | Типографика по нормам | Справочник Мильчина и Чельцовой, ГОСТ 8.417-2002, СанПиН 1.2.3685-21 (ТЗ, раздел 8.1) |

## 2. Слой 1. Лексика

Лексика общая для всех наших блоков: правила записи одинаковы в ```` ```конспект ````, ```` ```дракон ```` и ```` ```мат ````. Ребёнок учит их один раз.

### 2.1. Блок и строки

**Формально.** Конспект — это содержимое ограждённого блока Markdown с именем `конспект`. Текст делится на строки по символу перевода строки. Строка, первый непробельный символ которой `#`, — комментарий и пропускается.

**Простыми словами.** Конспект пишется между ```` ```конспект ```` и ```` ``` ````. Строка с `#` в начале — заметка для себя, на схему не попадает.

**Пример.**
````
```конспект
# черновик: проверить с 5 «Б»
тема: Признаки делимости
```
````

### 2.2. Отступы

**Формально.** Отступ строки — число ведущих пробелов; символ Tab считается за 4 пробела. Родитель строки — ближайшая предыдущая строка с **меньшим** отступом. Размер шага отступа не фиксирован, важно только сравнение «больше — меньше». Пустая строка вложенности не меняет (раздел 2.6).

**Простыми словами.** Как в Python: сдвинул строку вправо — она стала частью строки над ней. В редакторе клавиша Tab ставит нужное число пробелов.

**Пример.**
```
опр: Степень -> Это произведение одинаковых множителей.
  пример: 2⁵ = 2 · 2 · 2 · 2 · 2
```
Строка `пример:` сдвинута — это пример **к определению**, он будет нарисован под ним.

### 2.3. Ключевые слова

**Формально.** Ключевое слово стоит **в начале строки**, пишется **только строчными буквами** и отделяется двоеточием (у `правило` и `связь` двоеточие стоит после целей, раздел 3). Буква «ё» в ключевом слове равна «е». У каждого ключевого слова есть английский синоним (таблица 2.1), тоже только строчными. Слово с заглавной буквы («Тема:») ключевым не является и показывается как текст.

**Простыми словами.** Ключевые слова пишутся маленькими буквами в начале строки, как в Python: `тема:`, а не `Тема:`. Можно писать по-английски: `topic:`.

**Таблица 2.1. Ключевые слова и синонимы**

|---|---|---|
| `тема:` | `topic:` | 3.2 |
| `связка:` | `link:` | 3.3 |
| `стрелка:`, `двойная стрелка:` | `arrow:` | 3.4 |
| `правило:`, `правило → цели:` | `rule:` | 3.5 |
| `пример:`, `контрпример:` | `example:`, `counterexample:` | 3.6 |
| `связь A → B:` | `relation A -> B:` | 3.7 |

| `рисунок:` | `picture:`, `image:` | 3.9 |
| `код:` | `code:` | 3.10 |
| `опр:` (`определение:`) | `def:` | 3.11 |
| `теорема:`, `свойство:`, `признак:`, `следствие:`, `формула:`, `аксиома:`, `алгоритм:`, `закон:`, `метод:`, `команда:`, `единица:` | `theorem:`, `property:`, `criterion:`, `corollary:`, `formula:`, `axiom:`, `algorithm:`, `law:`, `method:`, `command:`, `unit:` | 3.11 |

**Устаревшие слова** понимаются, но с подсказкой: `вопрос:` → `тема:`, `почему:` → `стрелка:`, `понятие:` → просто `термин -> ответ`, `профиль:` → `схема:`.

### 2.4. Операторы

**Формально.** Операторы распознаются **вне** формул `$…$` и кода `` `…` ``:

| Оператор | Смысл | Где |
|---|---|---|
| `->` (на экране →) | «вопрос → ответ»: указатель и мнемоблок (запоминатель) | в любой строке без маркера |
| `><` | «против»: две стороны сравнения (очная ставка) | в любой строке без маркера; сильнее `->` |
| `\|` | разделитель частей | в `связка:` — `\|`; в строках Шеренги — ` \| ` с пробелами |
| `[часть]{подпись}` | разбор: подпись к части текста | в любом тексте |
| `{обоснование}` в конце строки выкладки | причина перехода | только в строке выкладки (3.6.2) |

**Простыми словами.** `->` — «что это / ответ», `><` — «не путать: это против того», `[ ]{ }` — подписать часть записи.

### 2.5. Экранирование и особые сочетания

**Формально.** Обратная косая черта отменяет служебный смысл следующего знака:

| Запись | Результат | Зачем |
|---|---|---|
| `\[` `\]` | `[` `]` | квадратные скобки, не разбор: «отрезок \[0; 1\]» |
| `\{` `\}` | `{` `}` | фигурные скобки, не подпись: «\{1, 2, 3\}» |
| `\\|` | `\|` | черта, не разделитель: модуль в ячейке «\|x\|» |
| `\$` | `$` | знак доллара, не формула |
| `\->` | `->` | стрелка буквами, не запоминатель |
| `\n` | новая строка внутри фигуры | только вне `$…$` и `` `…` `` |
| `\t` | отступ на 4 пробела внутри фигуры | только вне `$…$` и `` `…` `` |
| `\` в конце строки | строка продолжается на следующей | `\\` в конце — это сама косая черта |

Внутри `$…$` обратная косая черта принадлежит формуле: `$a \ne 0$`, `$\frac{1}{2}$`, `$\text{км}$`.

**Простыми словами.** Если нужен сам знак `[`, `{`, `|`, `$` — поставьте перед ним `\`. В формулах так не нужно: там свои правила.

**Пример.**
```
тема: Записи с особыми знаками
связка: Знак | Запись в тексте
Модуль -> \|x\| | \|−3\| = 3
Множество -> \{1, 2, 3\} | A = \{x : x > 0\}
```

### 2.6. Пустые строки и зоны

**Формально.** Пустая строка внутри фигуры — **отбивка** (увеличенный интервал); на верхнем уровне она ничего не значит. Строка из трёх и более дефисов `---` делит конспект на **зоны**; каждая зона раскладывается как отдельная схема, между зонами рисуется пунктирный разделитель. Настройки `схема:` действуют на свою зону, остальные настройки — на весь конспект.

**Простыми словами.** `---` — новая мысль, новая схема на том же листе.

**Пример.**
```
тема: Линейная функция
пример: y = [k]{угловой коэффициент}x + [b]{свободный член}
---
тема: Как k влияет на график?
k > 0 >< k < 0
```

### 2.7. Формулы и код в строке

**Формально.** `$…$` — формула в строке, `$$…$$` в начале и конце строки — выключная формула в рамке. Формулы набираются KaTeX (ТЗ 8.1): переменные курсивом, числа и единицы прямо. `` `…` `` — код в строке (моноширинный). Внутри формул и кода не действуют операторы и разбор.

**Простыми словами.** Формулы — между знаками доллара, как в обычном Markdown. Код — между обратными кавычками.

## 3. Слой 2. Строки конспекта

### 3.0. Грамматика строки (EBNF)

**Формально.** Нотация ISO 14977: `|` — или, `[ ]` — необязательно, `{ }` — повтор 0 и более раз, `"…"` — знаки как есть. `ПС` — перевод строки, `П` — один и более пробелов. Ключевые слова даны по-русски; английские синонимы (таблица 2.1) равноправны.

```ebnf
конспект        = зона , { разделитель , зона } ;
разделитель     = ПС , "---" , { "-" } , ПС ;
зона            = { строка , ПС } ;
строка          = отступ , ( комментарий | настройка | элемент ) | пустая ;
отступ          = { " " } ;                      (* Tab = 4 пробела *)
комментарий     = "#" , { знак } ;
пустая          = { " " } ;

настройка       = ключ , [ П ] , ( ":" | "=" ) , [ П ] , значение ;
ключ            = "схема" | "класс" | "ширина" | "начать с" | "нумерация" | "язык" ;

(* порядок альтернатив = приоритет разбора (раздел 3.1) *)
элемент         = ключевая | маркерная | выкладка | сравнение | запоминатель
                | вид_без_ответа | текст ;

ключевая        = тема | связка | стрелка | правило | пример | связь
                | выноска | рисунок | код ;
тема            = "тема" , ":" , строка_текста ;
связка          = "связка" , ":" , ячейка , { "|" , ячейка } ;
стрелка         = [ "двойная" , П ] , "стрелка" , ":" , строка_текста ;
правило         = "правило" , [ стрелка_к , цель , { "," , цель } ] , ":" , строка_текста ;
пример          = ( "пример" | "контрпример" ) , ":" , строка_текста ;
связь           = "связь" , П , цель , стрелка_к , цель , ":" , строка_текста ;
выноска         = ( "выноска" | "пояснение" | "уточнение" ) , [ П , ( "снизу" | "справа" ) ] ,
                  ":" , строка_текста ;
рисунок         = "рисунок" , ":" , описание | "![" , подпись , "](" , путь , ")" ;
код             = "код" , ":" , [ " " ] , строка_кода | "`" , строка_кода ;
стрелка_к       = [ П ] , ( "→" | "->" ) , [ П ] ;
цель            = подпись_части | текст_части ;       (* ищется в примере, 3.5 *)

маркерная       = пункт | шаг | маркер | черта | скобка | формула_в_рамке ;
пункт           = ( "-" | "–" ) , П , строка_текста ;
шаг             = цифры , ( "." | ")" ) , П , строка_текста ;
маркер          = ( "*" | "•" ) , П , строка_текста ;
черта           = "|" , П , строка_текста ;
скобка          = "}" , [ П , строка_текста ] ;
формула_в_рамке = "$$" , формула , "$$" ;

выкладка        = отношение , П , строка_текста , [ П , "{" , обоснование , "}" ] ;
отношение       = "=" | "=>" | "<=>" | "<=" | ">=" | "!=" | "<" | ">" | "≈" | "→" | "≡"
                | "⇒" | "⇔" | "≤" | "≥" | "≠" ;

сравнение       = [ строка_текста ] , "><" , [ строка_текста ] ;
запоминатель    = указатель , "->" , строка_текста ;
указатель       = [ "опр" , ":" , П | вид , ":" , П ] , строка_текста ;
вид             = "теорема" | "свойство" | "признак" | "следствие" | "формула" | "аксиома"
                | "алгоритм" | "закон" | "метод" | "команда" | "единица" ;
вид_без_ответа  = вид , ":" , строка_текста ;
текст           = строка_текста ;

строка_текста   = { фрагмент } ;
фрагмент        = обычный | формула_в_строке | код_в_строке | часть | экран ;
формула_в_строке= "$" , формула , "$" ;
код_в_строке    = "`" , строка_кода , "`" ;
часть           = "[" , [ строка_текста ] , "]" , "{" , [ подпись ] , "}" ;
экран           = "\[" | "\]" | "\{" | "\}" | "\|" | "\$" | "\->" | "\n" | "\t" ;
```

Дополнения, которые грамматикой не выражаются:
1. Ключевые слова и операторы распознаются только **вне** `$…$` и `` `…` ``.
2. `\` в конце строки (но не `\\`) склеивает строку со следующей через пробел **до** разбора.
3. Ячейки в строке Шеренги делятся сочетанием ` | ` (пробел, черта, пробел), в `связка:` — любой чертой.
4. Обоснование `{…}` в строке выкладки — это **последние** фигурные скобки строки, если перед ними не стоит `]` (иначе это подпись разбора).

### 3.1. Приоритет разбора строки

**Формально.** Строка относится к первому подходящему виду в порядке:
1. **настройка** (раздел 4);
2. **ключевое слово** в начале строки (3.2–3.10);
3. **маркер в начале строки**: `-`, `1.`, `*`, `|`, `}`, `$$…$$`, знак отношения;
4. **оператор внутри строки**: сначала `><`, затем `->`;
5. **вид без ответа** (`теорема: текст`);
6. **текст**.

Если строка с маркером содержит `->` или `><`, оператор показывается как текст и выдаётся подсказка. Если в строке и `><`, и `->`, строка понимается как сравнение (с подсказкой).

**Простыми словами.** Что стоит в начале строки, то и главное. Строка «`- Плавление -> переход в жидкость`» — это пункт списка, а не запоминатель: уберите дефис, если нужен запоминатель.

**Пример.**
```
тема: Переходы вещества
- Плавление -> переход из твёрдого в жидкое     ← пункт, «->» как текст, подсказка
Испарение -> переход из жидкого в газ            ← запоминатель
```

### 3.2. `тема:` — заголовок

**Формально.** `тема: текст` создаёт **Заголовок** зоны. Две строки `тема:` подряд с очной ставкой между ними дают схему «Двуглавый змей». Вложенные в тему строки: `выноска:`, `уточнение:`, `правило:` — рисуются справа от заголовка.

**Простыми словами.** Тема — это овал сверху. Можно поставить её вопросом: «Как сложить дроби?».

**Пример.**
```
тема: Как сложить дроби с разными знаменателями
  уточнение: Пример: 1/4 + 1/6
```

### 3.3. `связка:` — общая часть

**Формально.** `связка: A | B | …`. Одна часть — общая шапка Лестницы или Гребенки («Чтобы найти НОД:»). Две части — заголовки сторон Очной ставки. Две и более частей вместе со строками вида `признак -> a | b | …` — шапка столбцов **Шеренги**.

**Простыми словами.** Связка — то, что объединяет пункты: начало общей фразы или названия того, что сравниваем.

**Пример.**
```
тема: Комбинаторика: что выбрать?
связка: Перестановки | Размещения | Сочетания
Порядок важен? -> да | да | нет
```

### 3.4. `стрелка:` — вывод

**Формально.** `стрелка: текст` — блочная стрелка вниз и блок вывода. В сцене стрелка идёт к следующему элементу. В очной ставке одна `стрелка:` (или `двойная стрелка:`) — общий вывод под обеими сторонами; две строки `стрелка:` — отдельные выводы под левой и правой стороной.

**Простыми словами.** Стрелка — «значит…», «отсюда…».

**Пример.**
```
тема: Когда среднее, а когда медиана?
связка: Среднее | Медиана
Чувствительно к выбросам >< Устойчива к выбросам
стрелка: Если в данных есть выбросы, медиана честнее
```

### 3.5. `правило:` — правило со стрелкой к части

**Формально.** `правило → цель₁, цель₂: текст` (вместо `→` можно `->`). Цель ищется в **следующем** примере с разбором: сначала по подписи `{…}`, затем по тексту части `[…]`, затем по вхождению. Правило рисуется прямоугольной выноской над примером, со стрелкой к каждой цели. Правило, написанное **после** примера, относится к нему. `правило: текст` без целей — отдельный блок. Внутри запоминателя `правило:` — квадратная выноска под блоком.

**Простыми словами.** Правило со стрелкой показывает, к какой части примера оно относится.

**Пример.**
```
правило → остаток: Остаток всегда меньше делителя.
пример: [17]{делимое} = [5]{делитель} · [3]{неполное частное} + [2]{остаток}
```

### 3.6. `пример:` и `контрпример:`

**Формально.** На верхнем уровне сцены пример **с разбором** рисуется белой рамкой во всю колонку с капсулами частей и подписями; пример **без разбора** — белой рамкой «Пример». Вложенный в фигуру пример — привязанный: белая рамка под фигурой с клином к ней. `контрпример:` — то же, с заголовком «Контрпример ✗» тёмно-красным.

**Простыми словами.** Пример — белое (разберись), правило — жёлтое (запомни). Контрпример показывает частую ошибку.

#### 3.6.1. Разбор `[часть]{подпись}`

**Формально.** `[часть]{подпись}` выделяет часть капсулой и подписывает её. `[]{подпись}` — подпись к **пустому месту** (пунктирная черта): «здесь должна быть запятая». `[часть]{}` — капсула без подписи. Внутри части можно писать формулы и код; скобки внутри формулы разбор не прерывают. Текст примера **никогда не раздвигается** ради подписей: подписи раскладываются под ним по правилам раздела 7.4.

**Простыми словами.** Квадратные скобки — что подписать, фигурные — как подписать.

**Пример.**
```
пример: [a]{делимое} = [b]{делитель} · [q]{неполное частное} + [r]{остаток}
пример: Мы хотели пойти в кино[]{здесь запятая} но пошёл дождь.
```

#### 3.6.2. Выкладка

**Формально.** Строки, вложенные в `пример:` и начинающиеся со знака отношения и пробела, образуют **выкладку**: знаки выстраиваются в столбик, текст — после знака, обоснование `{…}` — курсивом справа за чертой. Ввод `=>`, `<=>`, `<=`, `>=`, `!=` показывается как ⇒, ⇔, ≤, ≥, ≠.

**Простыми словами.** Решение по шагам: каждая строка начинается со знака «=», «⇒» и т. п., причина — в фигурных скобках в конце.

**Пример.**
```
пример: 3(x − 2) = x + 4
  => 3x − 6 = x + 4     {раскрыли скобки}
  => 2x = 10            {перенесли с другим знаком}
  => x = 5
```

### 3.7. `связь A → B: текст`

**Формально.** Связь между двумя частями одного разбора: ломаная над примером от A к B со стрелкой в B и капсулой с текстом. A и B ищутся как цели правила (3.5). Строка `связь` после примера относится к нему.

**Простыми словами.** Связь показывает, что одна часть зависит от другой: «новое a получается из старого».

**Пример.**
```
пример: [a]{новое} = [a]{старое} + 1
  связь старое → новое: +1
```

### 3.8. `выноска:`, `пояснение:`, `уточнение:`

**Формально.** Выноска — скруглённый жёлтый блок с клином к фигуре-родителю. Положение: `справа` или `снизу`. Без уточнителя выноска запоминателя стоит справа, если её текст короткий (до 70 знаков) и в ней нет вложенных строк, иначе снизу; выноска пункта — снизу. В пронумерованной колонке ГНОМа выноска всегда под блоком. `уточнение:` — прямоугольная выноска (рядом с темой — справа от овала). `пояснение:` — синоним `выноска:`.

**Простыми словами.** Выноска — подсказка сбоку: пример, мнемоника, «не путать».

### 3.9. `рисунок:`

**Формально.** `рисунок: описание` или `![подпись](путь)` — место под рисунок. В редакторе — пунктирная рамка с описанием; при печати и экспорте — подключённый рисунок или ничего (ТЗ 8.1).

### 3.10. Код

**Формально.** `код: строка` или строка, начинающаяся с `` ` `` (нечётное число обратных кавычек), — строка кода; пробелы после метки сохраняются. Подряд идущие строки кода объединяются в один блок моноширинным шрифтом.

**Пример.**
```
`def f(n):
`    return 1 if n == 0 else n * f(n - 1)
```

### 3.11. Запоминатель `указатель -> ответ`

**Формально.** Строка `указатель -> ответ` — **запоминатель** ГНОМа: указатель (полая стрелка-пятиугольник слева) и мнемоблок (жёлтый прямоугольник с тенью).
- `опр: Термин -> Это …` — определение. Если термин из одного-двух слов, указатель получает вид «Что такое термин» (первая буква строчная, если второе слово не аббревиатура).
- `вид: имя -> ответ` (вид из таблицы 2.1: теорема, свойство…) — указатель «Вид имя»: `свойство: переместительное -> …` → «Свойство переместительное».
- `вид: ответ` без `->` — указатель «Вид».
- Вложенные строки — содержимое мнемоблока: маркеры `*`, черта `|`, скобка `}`, формула `$$`, текст, код, рисунок, пункты; выноски, примеры и правила — снаружи блока.

**Простыми словами.** Слева — вопрос, справа — ответ, который надо запомнить. Определение начинайте словом «Это…».

**Пример.**
```
опр: Модуль числа -> Это расстояние от нуля до точки на координатной прямой.
  * $|a| = a$, если $a ≥ 0$
  * $|a| = −a$, если $a < 0$
  | Модуль не бывает отрицательным.
```

### 3.12. Сравнение `левое >< правое`

**Формально.** Строка с `><` — **пара** очной ставки. Несколько пар подряд — многоэтажная очная ставка. Вложенные маркеры `* л: …` / `* п: …` уходят в левую / правую сторону (без метки — в левую). Особая форма — **пара списков**: строки `* …`, затем строка из одного `><`, затем строки `* …`.

**Простыми словами.** `><` — «не путать»: слева одно, справа другое, посередине стяжка.

**Пример.**
```
тема: Чем отличаются обыкновенная и десятичная дроби?
связка: Обыкновенная | Десятичная
* Записывается через черту: 3/4.
><
* Записывается через запятую: 0,75.
```

### 3.13. Пункты, шаги, группы

**Формально.**
- `- текст` — **пункт**. `1. текст` / `1) текст` — **шаг** (пункт с номером).
- Строка, у которой есть вложенные пункты, группы или текст, становится **группой**; двоеточие в конце её текста не показывается.
- Строка текста без маркера на верхнем уровне — пункт.

**Простыми словами.** Дефис — пункт, цифра с точкой — шаг алгоритма, строка с вложенными пунктами — заголовок группы.

**Пример.**
```
тема: Виды треугольников
По углам:
  - остроугольный
  - прямоугольный
По сторонам:
  - равнобедренный
```

## 5. Построение дерева конспекта

**Формально.** Строки зоны превращаются в дерево за четыре шага:
1. **Склейка** строк с `\` в конце.
2. **Разбор и вложение**: каждая строка классифицируется (3.1) и становится ребёнком ближайшей предыдущей строки с меньшим отступом. Настройки и комментарии в дерево не входят; пустая строка внутри фигуры — узел «отбивка».
3. **Нормализация:**
   - пункт или текст с вложенными пунктами, группами или текстом → **группа**;
   - текст верхнего уровня → **пункт**;
   - `* …` / `><` / `* …` → **пара списков**;
   - `связь` верхнего уровня → присоединяется к ближайшему предыдущему примеру;
   - правило с целями сразу **после** примера переставляется перед ним.
4. **Проверка вложенности** по таблице 5.1. Недопустимо вложенная строка не рисуется; выдаётся подсказка «… не может стоять внутри … — проверьте отступ».

**Таблица 5.1. Что может стоять внутри чего** (вариант «фигура и её содержимое»)

| Родитель | Допустимые дети |
|---|---|
| верхний уровень | тема, связка, запоминатель, сравнение, пункт, группа, правило, пример, стрелка, рисунок, код, выноска, маркер, текст, связь, формула |
| тема | выноска, уточнение, правило |
| запоминатель | маркер, черта, скобка, формула, код, рисунок, текст, пункт · *снаружи:* выноска, пример, правило |
| пункт, текст | то же, что запоминатель, + группа |
| группа | пункт, группа, текст, маркер, выноска, пример |
| сравнение | маркер (`л:` / `п:`) |
| пример | выкладка (текст со знаком отношения), связь, код, формула, маркер |
| правило | маркер, черта, скобка, формула, код, рисунок, текст |
| выноска | маркер, текст, формула, код, черта |
| маркер | маркер, текст |
| связка, стрелка, рисунок, код, связь, черта, скобка, формула | ничего |

Отбивка (пустая строка) допустима везде.

**Простыми словами.** Внутрь жёлтого блока можно положить маркеры, формулы и пояснения; пример и выноска вешаются на блок снаружи. Внутрь стрелки или связки ничего класть нельзя.

### 6.3. Выбор схемы

**Формально.** Если в зоне есть `схема:`, берётся она. Иначе проверки идут по порядку, побеждает первая подходящая:

| Шаг | Условие | Схема |
|---|---|---|
| 1 | есть `связка:` из ≥ 2 частей и строка `-> a \| b` | Шеренга |
| 2 | есть пример, правило, код, рисунок или связь; или есть стрелка без пар и не больше одной темы | Сцена |
| 3 | нет темы, есть запоминатели, нет пунктов и групп | ГНОМ |
| 4 | две темы | Двуглавый змей |
| 5 | есть пары `><` | Очная ставка: одна пара — простая или со связкой; несколько — многоэтажная |
| 6 | есть запоминатели | Батарея |
| 7 | есть группы | группа в группе — Дерево; группы и пункты — Лестница с гребенкой; только группы — Эполеты |
| 8 | есть шаги `1.` | Лестница (со связкой, если есть связка) |
| 9 | есть связка | ≥ 5 простых пунктов до 60 знаков — Гребенка со связкой; иначе Лестница со связкой |
| 10 | простые пункты до 32 знаков | помещаются в ряд — Линейка; до 12 — Шахматы; больше — Гребенка |
| 11 | ≥ 8 простых пунктов до 60 знаков | Гребенка |
| 12 | иначе | Лестница |

«Простой пункт» — пункт без вложенных строк, кроме выносок.

**Простыми словами.** Обычно схему выбирать не нужно: напишите текст, программа подберёт схему по его форме. Если хотите другую — `схема: дерево`.

**Английские названия для `scheme:`:** gnome, battery, ladder, ruler, chess, comb, epaulets, faceoff, tree, rank, scene, snake.

## 7. Правила раскладки

Правила раскладки не пишет учитель — их выполняет движок. Каждое правило проверяется эталоном и автоматической проверкой (раздел 10).

### 7.1. Цвет и смысл

| № | Правило |
|---|---|
| Р1 | Жёлтая заливка — только у того, что запоминают: указатель, мнемоблок, пункт, выноска, правило, подпись части, блок вывода |
| Р2 | Белое — примеры, разборы, формулы в рамке. Жёлтое на жёлтом запрещено: разбор внутри жёлтого блока рисуется во вложенной белой вкладке. *Основание: Венда, с. 126, 146 — главное не должно выглядеть так же, как второстепенное* |
| Р3 | Оранжевое — заголовки групп и колонок (связка, эполета, шапка Шеренги) |
| Р4 | Тень мнемоблока — сплошная коричневая со сдвигом 2 px (авторский стиль Паронджанова) |

### 7.2. Колонка, ширина, интервалы

| № | Правило |
|---|---|
| Р5 | **Одна колонка — одна ширина.** Фигуры одного ряда (Линейка, стороны очной ставки) и одного столбца (Шеренга, хребет) — одной ширины. В Сцене колонка во всю ширину, если в ней есть запоминатели или пункты; иначе 480 px |
| Р6 | **Ширина колонки указателей — по самому длинному слову** (но не больше 40 % ширины схемы, в Шеренге — 30 %): в указателях, шапках и заголовках слова не переносятся. Если слово не входит в шапку, кегль уменьшается на 1 px |
| Р7 | **Отбивки внутри фигуры:** части разного вида (текст, маркеры, формула, черта) разделены отбивкой; многострочные пункты — отбивкой; однострочные — плотно. *Основание: Венда, с. 340* |
| Р8 | **Выключка в колонке Сцены:** однострочные блоки — по центру, многострочные — влево |
| Р9 | **Номер ГНОМа — вплотную к мнемоблоку**, номера образуют ровный столбец (рис. 30 Паронджанова). Выноска пронумерованного блока — под ним |
| Р10 | **Дерево:** листья одной ширины по доступному месту; узлы одного уровня одной высоты; узел не уже своего текста в пределах своего поддерева |
| Р11 | **Очная ставка:** нижние блоки вывода выровнены по прямым сторонам колонок; общий вывод — от левого края левой колонки до правого края правой; раздельные — каждый под своей колонкой до начала острого угла |

### 7.3. Порядок и сторона («чем правее, тем хуже»)

| № | Правило |
|---|---|
| Р12 | Главное — слева и сверху; второстепенное — справа и снизу: выноски справа, примеры под фигурой |
| Р13 | **Правило со стрелкой** стоит над примером, стрелка — к своей части. Если над примером есть связь, правило ставится с той стороны связи, где у неё нет второго конца, и его стрелка входит в цель сбоку. Если там нет места (уже 130 px или уже самого длинного слова правила), правило ставится с другой стороны |
| Р14 | **Подпись связи** сдвигается прочь от правила, её край — у конца связи. Высота полосы связей — по самой высокой подписи связи |
| Р15 | Правило, написанное после своего примера, рисуется перед ним |

### 7.4. Подписи разбора

| № | Правило |
|---|---|
| Р16 | **Текст примера не раздвигается** ради подписей. Капсулы частей стоят на месте букв |
| Р17 | **Сначала — один ряд.** Если все подписи помещаются в один ряд в порядке своих частей и хвосты почти отвесны (сдвиг подписи от своей части не больше 70 px), подписи встают в один ряд. Порядок подписей = порядок частей, поэтому хвосты не пересекаются |
| Р18 | **Иначе — по рядам, сверху вниз.** Подпись может сдвинуться вбок за свою часть (хвост наклонный, сдвиг до 70 px), чтобы встать в ряд выше. Из допустимых мест выбирается самый верхний ряд, а в нём — самый короткий хвост |
| Р19 | **Допустимое место:** подписи одного ряда не ближе 10 px; подпись не закрывает место (±16 px), где пройдёт хвост ещё не размещённой подписи; наклонный хвост не проходит над чужой частью, к которой хвост ещё не проведён; хвост не пересекает чужие подписи и хвосты и не подходит к чужой подписи ближе 10 px по оси (хвост — клин шириной до 12 px) |
| Р20 | Новый ряд создаётся, только если по правилам Р17–Р19 подписи не помещаются в существующие |
| Р21 | Больше 7 подписей в одном примере — подсказка «разбейте пример на два» |

### 7.5. Типографика

| № | Правило |
|---|---|
| Р22 | **Неразрывные связки:** короткий предлог, союз или частица (в, на, с, к, и, а, но, не, по, о, от, до, из, за, у, для, при, без, над, под, про, или, что, же, да) — со следующим словом; слово — с тире после него; число — с единицей измерения (в т. ч. составной: м/с, км/ч, кВт·ч, м²) и со следующей группой разрядов; № и § — с числом |
| Р23 | **Короткая концевая строка** (короче 40 % самой длинной) выравнивается подбором меньшей ширины без новых переносов |
| Р24 | **Переносы по слогам** — только в тексте блоков и листьях Дерева и только если слово не помещается целиком. Правила переноса: после гласной (но не перед удвоенной согласной); после ь, й; между удвоенными согласными; после р, л, м, н перед согласной; перенесённая часть не начинается с ь, ъ, й и с сочетания «согласная + ь»; в каждой части есть гласная, части не короче двух букв |
| Р25 | **Шрифт и кегль.** Текст — PT Sans, код — PT Mono (ПараТайп, OFL). Кегль по классу: 1–6 кл. — 15 px, 7–9 — 14, 10–11 — 13, без класса — 14 (в программе — в пунктах для печати, ТЗ 8.1) |
| Р26 | **Формулы** — KaTeX (ТЗ 8.1): курсив переменных, стрелки векторов, настоящие индексы, двухэтажные дроби в `$$…$$` |

### 7.6. Запреты

**Формально.** Рисунок ГРАФа не может содержать:
1. пересечений хвостов, линий и связей между собой;
2. наложений фигур (кроме вложения одной в другую);
3. текста, выходящего за свою фигуру;
4. хвоста ближе 4 px к чужой фигуре и хвостов ближе 3 px друг к другу (кроме сходящихся к одной части);
5. жёлтого на жёлтом (Р2).

Запреты гарантирует движок; их выполнение проверяет автоматическая проверка на всём эталоне (раздел 10). *Основание: Венда, с. 377 — минимум пересечений и изгибов линий.*

**Простыми словами.** Ничего не пересекается, не налезает и не вылезает за рамку — это забота программы, а не учителя.

## 8. Связь слоёв

### 8.1. Строка → операция

**Формально.** Каждая строка текста — одна операция над заготовкой схемы.

**Таблица 8.1. Строка → операция над рисунком**

| Строка | Операция | Фигуры |
|---|---|---|
| `тема:` | поставить Заголовок (вторая тема — второй Заголовок) | Ф1 |
| `связка:` | поставить Связку / шапку сторон / шапку столбцов | Ф6 |
| `указатель -> ответ` | добавить запоминатель в колонку; в Шеренге — строку таблицы | Ф2 + Ф3 (+ Ф4) |
| `опр:` / `вид:` перед указателем | задать вид указателя («Что такое…», «Свойство…») | Ф2 |
| `левое >< правое` | добавить этаж очной ставки | Ф2 + Ф9 + Ф8 |
| `- пункт`, `1. шаг` | добавить пункт к хребту, шине или колонке | Ф5 |
| строка с вложенными пунктами | добавить группу (эполету, ветвь дерева, гребенку под пунктом) | Ф7 / Ф5 |
| `* маркер`, `\| черта`, `} скобка`, `$$формула$$` | наполнить фигуру-родителя | Ф21, Ф22, Ф23, Ф20 |
| `выноска:` / `уточнение:` | повесить выноску на фигуру-родителя | Ф10 / Ф11 |
| `правило → цель:` | поставить правило над следующим примером со стрелкой к части | Ф11 |
| `пример:` (с `[…]{…}`) | поставить рамку разбора; каждая `[часть]{подпись}` — капсула и подпись | Ф13, Ф14, Ф15, Ф16 |
| `пример:` (без разбора), `контрпример:` | поставить рамку примера (вложенный — под фигурой с клином) | Ф12 |
| `= …`, `=> …` под примером | добавить строку выкладки | — |
| `связь A → B:` | провести связь над разбором | Ф17 |
| `стрелка:` | поставить блочную стрелку и блок вывода | Ф18 + Ф19 |
| `рисунок:` | поставить место рисунка | Ф25 |
| `` ` ``, `код:` | добавить строку в блок кода | Ф24 |
| `---` | начать новую зону с новой заготовкой | Ф27 |
| настройка | изменить параметры зоны или конспекта | — |

### 8.2. Определение правильного конспекта

**Формально.**
1. **Правильно построенный рисунок** — рисунок, полученный из заготовки схемы операциями таблицы 8.1 по правилам раскладки раздела 7. Движок строит только такие рисунки: для любого текста рисунок правильно построен (аналог теорем 36–37 Паронджанова о ДРАКОН-схемах).
2. **Правильный конспект** — текст, для которого движок не выдаёт ни одной подсказки раздела 9.
3. Правильность **содержания** (верно ли утверждение) языком не проверяется — это работа учителя.

**Простыми словами.** Программа всегда нарисует аккуратно. Если подсказок нет — конспект написан по правилам. А вот верно ли написано по существу, проверяет учитель.

## 9. Подсказки

**Формально.** Подсказка — сообщение под рисунком. Рисунок при этом строится всегда. Подсказки выдаются: при вводе — внутри блока известного типа (```` ```конспект ````); при просмотре — в панели замечаний документа. Текст подсказки говорит, **что** не так и **как** исправить.

**Простыми словами.** Программа не ругается и не отказывается рисовать — она советует.

## 10. Эталон и приёмочные тесты

**Формально.** Эталон v8 — 249 примеров в `graf/examples*.js` и их рисунки `graf/etalon/NNN.svg` с манифестом `graf/etalon/manifest.json` (группа, название, схема, подсказки, контрольная сумма). Любое изменение движка проверяется командой:

```bash
cd graf && python3 build.py && node tests/run.js
```

Команда выполняет три проверки:
1. **Сверка с эталоном:** рисунок и подсказки каждого примера должны совпасть с эталонными: текст и фигуры — точно, координаты и размеры — с допуском 3 px (запасные шрифты для греческих букв и знаков ⇒ ⊥ ∠ ∈, которых нет в PT Sans, на разных машинах округляют ширину по-разному). Расхождение — либо ошибка, либо осознанное изменение; во втором случае эталон пересъёмывается командой `node tests/run.js --update` **только по решению заказчика**.
2. **Геометрия** (`tests/geo.js`): запреты раздела 7.6 — пересечения хвостов, линий, связей; наложения фигур; текст за рамкой; зазоры хвостов (4 px до фигуры, 3 px между хвостами); пологие длинные хвосты.
3. **Типографика** (`tests/typo.js`): висячие предлоги, тире в начале строки, отрыв числа от единицы, дефис вместо минуса, мелкий кегль.

**Состав эталона.**

## 11. Резерв и границы версии 8

| Что | Статус |
|---|---|
| `рисунок: #имя` — ссылка на рисунок или блок документа | резерв (общий механизм имён блоков `#имя`) |
| Библиотека эталонных рисунков (геометрия, физика) | резерв |

Термины Паронджанова; идея схемокурса — Г. А. Гуленков (ИТО-2000) |
| Перекрёстные ссылки ГРАФ ↔ ДРАКОН, трассировочная таблица | направление (файл «ДРАКОН и ГРАФ в паре») |

| Визуальный редактор ГРАФ, панель «кубиков» | вне версии 8: редактор текстовый, ввод ускоряют горячие клавиши и подсказки |
| Темы «проектор» и «сдержанная», режим «сжато», разрыв схем между страницами | предложено, не реализовано |
| Ограничение колонки текста ≈ 65 знаками в широких блоках | предложено (замечание 9 дизайнера), не решено |
| **Выделение различий в паре `><`**: слова, которыми стороны различаются, выделяются автоматически («наибольший» / «наименьший») | резерв. Основание: Венда — различительные признаки на первом месте среди факторов сложности (с. 76, 385) |
| **Подсветка при наведении** (интерактивный просмотр): правило подсвечивает свою цель в примере, подпись — свою часть | резерв. Основание: Венда, с. 143–146 — высвечивание актуального контура |
