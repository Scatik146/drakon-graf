# КуМир: откуда он у Митькина, Qumir и что из этого нам нужно

*13.11.2026. Прочитаны README и документация `github.com/QumirLabs/qumir` и `github.com/QumirLabs/qumir-service` (`docs/ru`, `examples`). Программы, которые строит наша обёртка, проверены запуском на qumir.dev.*

## 1. Откуда КуМир

- **КуМир** — школьный язык и среда НИИСИ РАН с русскими ключевыми словами. На нём пишут задания ОГЭ и ЕГЭ с исполнителями (Робот, Чертёжник).
- **Qumir** (Алексей Озерицкий, BSD-2) — новый компилятор КуМира на C++/LLVM. На нём работает **qumir.dev**, «КуМир онлайн». Там есть Робот, Черепаха, Чертёжник и Рисователь. Отдельная школьная установка — педобраз.рф/kumir.
- **ДРАКОН-КуМир** — генератор Митькина в ДраконТех (`drakontechgen.js`, `KUMIR2606`). По словам Митькина, его код работает в классическом КуМире и на qumir.dev.

## 2. Как наш КуМир пишет задачи ОГЭ

Свой генератор (обёртка `drakon-shema` 1.4, кнопка «Код») проверен **запуском на qumir.dev**:

| Программа | Ввод | Результат |
|---|---|---|
| Сумма чисел, кратных 3 и оканчивающихся на 4 (задача 15 ОГЭ, «нц для», «если … и …») | 5; 24 54 7 114 4 | 192 ✓ |
| Максимум последовательности | 4; 3 17 5 9 | 17 ✓ |
| Первое чётное (выход из цикла) | 4; 3 8 6 9 | 8 ✓ |
| Счёт до нуля (`нц … кц при`) | 5 7 0 | 2 ✓ |
| Оценка (`выбор / при / иначе`) + `если` | 2 | «старайся — пересдача» ✓ |
| Робот у стены (`использовать Робот`, `нц пока не справа свободно`) | — | запускается ✓ |
| `нц 3 раз` | — | `***` ✓ |
| «далее» и «выход» в «нц для» | — | `1 3 5 7` ✓ |

Код получается таким, как его пишут в ОГЭ: `нц пока условие`, `нц для i от 1 до n`, `кц при`, `выбор / при`.

Генератор Митькина цикл «пока» пишет как `нц пока да … выход … кц`. Это правильно, но так в ОГЭ не пишут. Поэтому для КуМира и Python мы взяли свои генераторы.

Найдено и исправлено при проверке:
- КуМир не принимает в имени алгоритма слово, начинающееся с цифры («кратных 3»). Имя `алг` теперь чистится от цифр и служебных слов.
- `использовать Робот` переносится в начало файла.
- `далее` (к следующему шагу) понимает только Qumir. В классическом КуМире такой команды нет, поэтому обёртка о ней предупреждает.

## 3. Облегчит ли Qumir жизнь

**Полностью — нет.** qumir.dev **компилирует программу на сервере** (`qumirc`), а в браузере только запускает результат. Значит:
- без интернета, из сетевой папки, КуМир через Qumir не запустить;
- встроить его окном в наш сайт тоже нельзя: окно примеров `embed.html` принимает сообщения только со своего адреса.

**Частично — да:**
1. **Кнопка «Открыть в КуМире онлайн».** Сервер разрешает запросы с любых сайтов (CORS `*`) и умеет создавать ссылку на программу (`POST /api/share` → `qumir.dev/s/<id>`). Значит, программу по схеме можно одним нажатием открыть на qumir.dev вместе с вводом. В ссылку можно положить и поле Робота: файлы проекта передаются вместе с программой, и файл `*.fil` qumir.dev показывает как поле Робота. Обстановку ученик потом правит в **редакторе обстановок** qumir.dev (кнопка edit над полем: стены, клетки, положение Робота, размер поля). **Решение учителя (13.11):** это делаем **в онлайн-версии редактора**; в офлайн-версии (сетевая папка) таких кнопок нет. Каждое нажатие создаёт общедоступную ссылку на qumir.dev — об этом надо сказать в интерфейсе.
2. **Справочник синтаксиса** `docs/ru/syntax.md` — по нему сверяем генератор: `кц при`, `далее`, `выбор/при` с условиями, `шаг`.
3. **Формат поля Робота `.fil`** и описание исполнителей (`docs/ru/robot.md`, BSD-2). Пригодится, когда будем делать своего Робота для работы без интернета (ТЗ, раздел 5).
4. **Примеры** `examples/` (Робот, сортировки, строки, математика) — готовые эталоны для тестов.
5. **oz-lang** — промежуточный язык Qumir. Можно было бы компилировать в него наши схемы, но для школы это лишнее.

## 5. Полная проверка репозиториев (13.11, вечер)

Проверены `resetius/qumir` (BSD-2, коммит от 13.11.2026) и `QumirLabs/qumir-service` (BSD-2, Qumir Labs). Обе лицензии разрешают брать код в наш проект, если сохранить строку об авторах и текст лицензии.

- **Исполнители уже есть в браузерной среде выполнения** — `qumir/runtime/js/`: `robot.js` (Робот, сам читает `.fil`), `turtle.js` (Черепаха), `drawer.js` (Чертёжник), `painter.js` (Рисователь), `keyboard.js`, `io.js`. Поле рисуется на странице, где запущена программа, — то есть **у нас в документе**.
- **Ввод без общей памяти:** программа ждёт ввода через сопрограммы (`future.js`), поэтому заголовки и SharedArrayBuffer не нужны.
- **Ограничение:** перевести КуМир в WebAssembly может только компилятор (C++/LLVM), в браузере его нет. Есть три пути:
  1. компилировать на qumir.dev (`POST /api/compile-wasm`, CORS `*`) и выполнять у себя их средой выполнения — интернет нужен только на сам перевод;
  2. поднять свою копию `qumir-service` (нужен сервер);
  3. в офлайн-версии положить в программу `qumirc` — всё работает без сети.
- Перед тем как пользоваться их сервером из нашего редактора, написать авторам: код разрешён лицензией, а нагрузка на сервер — это просьба.

**Вывод:** блок ```` ```кумир ```` живёт. «Выполнить» — перевод на qumir.dev, исполнение и поле Робота — у нас; кнопка «Открыть в КуМире онлайн» (§ 3) остаётся. Свой Робот из § 4 делать не нужно — берём их `robot.js`.
