2. **Ваша догадка подтверждается текстом самого Паронджанова, но с уточнением.** В книге прямо сказано: знания делятся на процедурные («как») и декларативные («что»). ГРАФ — нотация для **декларативных**, ДРАКОН — для **процедурных**. Про «структуры данных» автор не пишет. Однако структура данных — частный случай декларативного знания, так что пара «ДРАКОН — алгоритм, ГРАФ — данные этого алгоритма» лежит точно в его логике.
3. **У самого ДРАКОНа своего языка для данных нет.** В описании языка и его теории данные упоминаются только как «величины», а для них предлагался отдельный **табличный** язык ФЛОКС (связка ГРАФИТ-ФЛОКС). Этот вывод важен для нас: естественный спутник алгоритма — **таблица**, а табличная схема у нас уже есть — **Шеренга**.
4. **Предложение: пять точек сопряжения**, без изменения обоих языков (раздел 3):
   - общая лексика ввода;
   - общий визуальный словарь;
   - **трассировочная таблица** как мост «алгоритм ↔ данные»;
   - перекрёстные ссылки;
   - карточка задачи «Дано — Найти — Решение».

## 2. Чем ДРАКОН и ГРАФ уже похожи

Сходство глубже, чем кажется. Это один «почерк» автора:

| Правило | ДРАКОН | ГРАФ |
|---|---|---|
| Линии | только горизонтальные и вертикальные, без пересечений | то же |
| Стрелки на линиях | почти нет (только в циклах) | запрещены |
| Направление | время течёт сверху вниз | чтение сверху вниз, слева направо |
| Главное и второстепенное | главный маршрут — по шампуру, «чем правее, тем хуже» | главное в Заголовке и мнемоблоках, пояснения — в выносках справа |
| Заголовок | икона «Заголовок» — скруглённая рамка вверху | Заголовок — овал вверху |
| Комментарий | икона «Комментарий» | выноска |
| Силуэт | ветки в ряд, сверху их названия | Линейка: шина и элементы в ряд |
| Разрезание длинного | «разрежь великана»: сложное условие → цепочка простых вопросов | «одна зона — одна мысль», сложный абзац → зоны с маркерами |
| Стандартное начертание | канон, отклонения недопустимы | канон, отклонения недопустимы |

Отсюда вывод: **органичность достигается не новыми фигурами, а единым оформлением и общими правилами ввода.**

## 3. Пять точек сопряжения (предложение, в прототип не внесено)

### 3.1. Одна лексика для всех наших блоков

Всё, что вы решили для конспекта, переносится на текстовый ДРАКОН без исключений:
- отступы и Tab как в Python;
- ключевые слова только строчные, без «ё»;
- английские синонимы;
- `#` для комментариев, `\n`, `\t`, `\` для продолжения строки, общее экранирование;
- подсказки вместо отказа, подсказки при вводе внутри блока.

Ребёнок учит **одни правила записи** и переходит из `конспект` в `дракон` без переучивания. Технически это один общий лексер для всех наших блоков (решение для программиста).

### 3.2. Общий визуальный словарь

- **Одна выноска на оба языка.** Комментарий в ДРАКОН-схеме рисуется той же жёлтой выноской, что в ГРАФе. Это уже было записано в v1, теперь обосновано и со стороны ДРАКОНа.
- **Один стиль Заголовка**, общий шрифт, общая толщина и цвет линий (коричневый контур, как в ГРАФе). DrakonWidget это позволяет: в нём настраиваются тема и цвета.
- **Роли цветов не пересекаются.** В ДРАКОНе иконы светлые; жёлтая заливка остаётся за ролью «запомни» и в ДРАКОН не попадает. Иначе нарушится правило «жёлтое — запомни».

### 3.3. Мост «алгоритм ↔ данные»: трассировочная таблица

Это главное предложение. В школьной информатике есть классическое упражнение — **таблица трассировки**: строки — шаги, столбцы — значения переменных. По сути это и есть «данные в алгоритме». На нашем языке это готовая **Шеренга**:

````
```дракон
… алгоритм Евклида …
```

```конспект
тема: Трассировка: НОД(48, 18)
связка: a | b | остаток
Шаг 1 -> 48 | 18 | 12
Шаг 2 -> 18 | 12 | 6
Шаг 3 -> 12 | 6 | 0
стрелка: Остаток 0 — ответ: НОД = 6
```
````

- ДРАКОН показывает **управление** (куда идём), Шеренга показывает **состояние данных** (что лежит в переменных).
- В режиме «Самопроверка» ячейки скрыты, и ученик сам заполняет трассировку. Это готовое упражнение ОГЭ и ЕГЭ.
- **На будущее, этап «генерация Python из ДРАКОНа»:** программа может *сама* построить такую Шеренгу, запустив алгоритм и записав значения переменных по шагам. Кнопка «Показать трассировку» под ДРАКОН-схемой.

Это прямой наследник идеи ГРАФИТ-ФЛОКС (схема + таблица величин), но в наших фигурах.

### 3.4. Перекрёстные ссылки

- Икона ДРАКОНа «Вставка» (вызов подпрограммы) может ссылаться на конспект: `вставка: НОД → #нод`. Щелчок открывает карточку «Что такое НОД».
- В конспекте строка `алгоритм: Евклида -> #евклид` открывает ДРАКОН-схему.
- Это тот же резерв `#имя`, что уже записан для `рисунок: #имя`. **Новых слов не нужно**, только общий механизм имён блоков в документе.

### 3.5. Карточка задачи «Дано — Найти — Решение»

Типовая форма записи задачи в физике и математике ложится на три наших блока:

| Часть | Блок | Почему |
|---|---|---|
| **Дано, найти** | `конспект`: Батарея или Шеренга величин с единицами (`m -> 50 кг`) | декларативное: что известно |
| **Решение (ход)** | `дракон`, если есть ветвления; иначе выкладка | процедурное: как решать |
| **Вычисление** | выкладка или `python` | проверка числом |

Это и есть «органичная пара» на уровне урока: одна задача, три блока, единое оформление.

## 4. Что из этого следует для грамматики

Выводы анализа **не меняют язык конспекта**. Всё, что нужно, уже есть: Шеренга, выкладка, резерв `#имя`. Для формальной грамматики добавляются два требования:

1. **Лексика описывается отдельным общим документом** для всех наших блоков (`конспект`, `дракон`, `мат`, `диаграмма`…), а грамматика конспекта на него ссылается.
2. **Механизм имён блоков** `#имя` описывается один раз и общий для всех блоков. Само имя задаётся в заголовке блока: ```` ```конспект #нод ````.
