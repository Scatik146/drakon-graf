## 1. Решения учителя

1. **Ядро — JS, Prolog живёт внутри.** JS — корпус и всё, что видит человек (редактор, рисование, страница); Prolog — язык: разбор, правила, проверка, генерация примеров и тестов. Связь — через JSON.
2. **Онлайн в приоритете.** В браузере — SWI-Prolog в WebAssembly (swipl-wasm). Tau Prolog (чистый JS, работает с `file://`) — запасной вариант для будущего офлайна.
3. **Полный перенос разборщика на Prolog не делаем.** Эксперимент своё доказал; переписывать работающий JS ради переноса — мало пользы.
4. **Итоговая цель:** Drakon.Tech Митькина — алгоритмы; **расширенный ДРАКОН-ГРАФ** — данные, структуры и правила; стыкуются через общий словарь. Базовый ГРАФ остаётся для конспектов школьников и студентов.
5. **«Форто-пролог» — нотация и стиль, а не свой исполнитель:** словарь маленьких слов (Forth) + факты и правила (Prolog) + картинка (ГРАФ). Исполнение — SWI-Prolog.

## 3. ДРАКОН-ГРАФ ⇄ Prolog: черновик соответствий

| ДРАКОН-ГРАФ | Prolog |
|---|---|
| `тема:` | модуль |
| запоминатель `указатель -> ответ` | факт |
| `правило:` | правило `голова :- условия` |
| `связь A -> B` | отношение |
| `пример:` / `контрпример:` | запрос, который истинен / ложен (тест) |
| вложенность | структура данных |

Главная трудность: в ГРАФе нет **переменных**. Начать с подмножества «факты + простые правила» (Datalog). Алгоритмическая часть Prolog (рекурсия по спискам, арифметика, отсечение) — естественнее ДРАКОНом.

**Куда ещё может выгружать расширенный ГРАФ:** Prolog (ядро), Datalog, ASP; JSON Schema, TypeScript, Python dataclasses, SQL; RDF/OWL, Cypher; Mermaid, PlantUML, Graphviz; тесты из `пример:`/`контрпример:`. Обратно — из SQL, JSON Schema, базы фактов. Первые цели: Prolog, JSON Schema, SQL (уроки баз данных), Mermaid.

## 4. Ниша (быстрый обзор, не исследование рынка)

- **У Митькина уже есть больше, чем алгоритмы:** DRAKON Editor умеет диаграммы состояний, «сущность-связь» и классов; DrakonHub бесплатен для учеников и учителей. Значит, ценность расширенного ГРАФа — **правила и единая эргономика**, а не схемы данных как таковые. Дополнять, а не дублировать.
- **«Визуальные правила → Prolog»:** VisiRule (LPA, платный; слои «схема → Flex → Prolog»), академические XTT/Mirella, Grailog, Nemo Explain Visualizer (Datalog, 2026). Ниша есть, узкая, англоязычная.
- **Схемы данных из текста** (DBML / dbdiagram.io, DrawSQL) — поле занято; можно выгружать в DBML.
- **Свободно:** данные + правила + алгоритмы в одной нотации с когнитивной эргономикой; русскоязычное сообщество ДРАКОНа (бизнес-процессы, клиническая медицина: критерии и признаки — правила рядом с алгоритмами лечения); «человек проверяет ИИ по картинке»; путь «школа → вуз → профессия».

## 6. Решения 15.11: расширенный ГРАФ, режим знаний

**Мерило понятности:** картинку одинаково хорошо читают 2–4, 5–6, 7–9, 10–11 классы и учителя всех предметов, разного возраста.

1. **Включение:** настройка `режим: знания`. Без неё конспект — обычный, ничего не ломается.
2. **Переменная — это запоминатель.** `А -> ?` — запоминатель с пустым ответом (неизвестное). Ответ Prolog — те же запоминатели с найденным ответом: `кто -> Иван`. Вопрос и ответ — одна фигура. Вопросительные слова (`кто`, `что`, `кого` …) в запросе — переменные сами по себе.
3. **Факт:** `связь Иван -> Пётр: родитель` → `родитель(иван, петр).` Подпись связи — имя отношения.
4. **Правило:** `правило: А предок В, если А родитель Б и Б предок В`. Каждое условие — ДРАКОН-вопрос; у правила есть ДРАКОН-схема «как это проверяется»: условия — иконы «Вопрос», `и` — вопросы подряд по шампуру, несколько правил одного имени — ветки силуэта, поиск («найти такого Б») — цикл «Для каждого», ответ — конец схемы. Работают все встроенные механизмы ДРАКОНа. ГРАФ — что верно (декларативное прочтение), ДРАКОН — как проверяется (процедурное).
5. **Тесты и запросы:** `пример:` — должно выводиться, `контрпример:` — не должно; `запрос:` — вопрос к базе (не `вопрос:` — это устаревший синоним `тема:`).
