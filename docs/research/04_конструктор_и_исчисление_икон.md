# Конструктор алгоритмов и исчисление икон: что это значит для ГРАФа

*К ТЗ «Живой учебник». Прочитаны подряд: часть 6 книги «Учись писать, читать и понимать алгоритмы» (с. 393–424, главы 32–33, 37 тезисов, рисунки 231–250) и глава 34 «Исчисление икон» (с. 427–435). Это последний материал перед формальной грамматикой.*

---

## 0. Главное

1. **У Паронджанова правильность схемы определяется не списком запретов, а способом построения.** Правильная схема — та, что получена из **заготовки** (аксиомы) конечным числом **разрешённых операций** (правил вывода). Всё остальное ложно. Отсюда его вывод: в конструкторе ошибки графического синтаксиса «принципиально невозможны».
2. **У нас та же гарантия, только получена другим путём.** У Паронджанова сначала форма, потом текст: пользователь собирает «слепыш» из кубиков и затем вписывает надписи. У нас сначала текст, а форма выводится: ученик пишет текст, программа сама строит схему. Любой текст рисуется правильно построенной схемой, а нарушения превращаются в подсказки. Наш путь удобнее для Markdown и для детей, но его нужно **так же строго описать**.
3. **Отсюда структура формального описания ГРАФа — три слоя:**
   - **лексика** — общая для всех наших блоков;
   - **текстовый синтаксис** (EBNF) — что ученик пишет;
   - **визуальный синтаксис в духе исчисления икон** — алфавит фигур, заготовки схем, операции, обязательные и необязательные места, запреты.

   Связь слоёв: каждая строка текста — это одна операция над заготовкой.
4. **Важное отличие, наш вклад:** ДРАКОН формализует только слепыш, а текст внутри икон остаётся вне формализма. ГРАФ формализует и **уровень строки**: разбор `[…]{…}`, выкладку, операторы `->`/`><`, формулы. Поэтому грамматика ГРАФа **двухуровневая**: блоки (слепыш) и строки (надписи). Режим «слепыш» в прототипе уже есть, он показывает ровно первый уровень.
5. **Из главы 32 берём три практических правила:**
   - равная ширина фигур в одном ряду или колонке;
   - структуризация текста внутри фигуры (отбивки, маркеры, заголовок без маркера);
   - два режима: «схема-картинка» и «исполняемая схема».
6. **Лист «Евклид: ДРАКОН и ГРАФ» исправлен** (см. раздел 6).

## 2. Соответствие понятий: ДРАКОН → ГРАФ

| ДРАКОН (тезис) | ГРАФ | Комментарий |
|---|---|---|
| Иконы — визуальный алфавит (т. 1) | **Фигуры**: овал Заголовка, мнемоблок (жёлтый), белый блок, рамка определения, выноска, ячейка, шина Линейки, стрелка зон, пунктирный якорь `[]`, вкладка разбора | Алфавит ГРАФа надо перечислить так же явно, как рис. 17 |
| Заготовки-аксиомы (т. 2) | **Заготовка каждой из 17 схем** — схема с одним Заголовком без содержания | 17 аксиом вместо двух. Это нормально: у нас 17 «жанров» |
| Атом, ввод атома (т. 8–10) | **Строка-конструкция**: `опр:`, `- пункт`, `пример:`, `выноска:`… Каждая строка — одна операция «ввести фигуру» | Связь «текст → операция» и есть мост между EBNF и визуальным синтаксисом |
| Валентные точки (т. 9) | **Места, куда можно вставить**: таблица ALLOW («фигура и её содержимое») | ALLOW — наш аналог списка валентных точек |
| Критические точки (т. 16–19) | **Обязательные части**: у Очной ставки две стороны; у Шеренги `связка:` и хотя бы одна строка; у `правило → цель` есть цель; у разбора `[часть]` есть `{подпись}`; у схемы есть `тема:` | Нарушение — подсказка «не хватает…», схема всё равно рисуется |
| Нейтральные точки (т. 20) | **Необязательные места**: выноска, пример, контрпример, уточнение | |
| Пустой атом недопустим в законченной схеме (т. 14) | **Пустая фигура** → подсказка | `[]` — не пустой атом, а **намеренный** якорь пустого места; это надо прописать явно |
| Матрёшка (т. 22) | **Вложенность** (вариант Б): группа в группе, разбор в примере | Глубину ограничиваем подсказкой (не больше 3 уровней) |
| Лиана, пересадка и заземление | **Связи и стрелки**: `связь a → b`, `стрелка:`, ветви Дерева | Линии не пересекаются и не идут вверх (т. 28) |
| «Сиамские близнецы» — второй вход в ветку запрещён (рис. 247) | **У узла Дерева один родитель**; общий потомок двух узлов — подсказка «это не Дерево, возьми Сцену или связи» | Один и тот же запрет в обоих языках |
| Пределы: 16 вариантов, 32 ветки (т. 31–32) | **Мягкие пределы ГРАФа**: столбцов Шеренги ≤ 5, пунктов в Батарее ≤ 7, зон ≤ 5 → подсказка «разрежь великана» | Пределы ДРАКОНа технические, наши — психологические (7 ± 2) |
| Рокировка (эквивалентное преобразование) | Обмен сторон Очной ставки, перестановка столбцов Шеренги | Смысл не меняется; в редакторе это одна команда |
| Т. 36–37: «окончательное определение» примитива и силуэта | **Определение:** правильный конспект — текст, который разбирается без подсказок; его схема — результат применения операций к заготовке | Формулировка для грамматики |
| Семантика «истинности» тривиальна (гл. 34, § 9) | То же: «правильно построен» = «выводим». Смысловая верность — вне грамматики | |

## 3. Что меняется в плане формализации ГРАФа

Структуру документа «Формальное описание языка ГРАФ» предлагаю такую (в духе гл. 33–34, но для текстового языка):

1. **Лексика** (общая для ```конспект, ```дракон, ```мат…): символы, отступы и Tab как в Python, ключевые слова только строчные, «ё» = «е», английские синонимы, `\n`, `\t`, `\` для продолжения строки, экранирование `\[ \] \{ \} \$ \| \->`, `#` для комментария.
2. **Текстовый синтаксис** (EBNF), два уровня:
   - уровень блока: настройки, `тема:`, строки-конструкции, отступы, зоны `---`;
   - уровень строки: разбор `[…]{…}`, `[]`, выкладка (знаки отношения в начале строки, `{обоснование}` в конце), операторы `->`, `><`, `|`, формулы `$…$`, код `` `…` ``.

   Здесь же — приоритет внутри строки (вариант А: ключевое слово → маркер → оператор).
3. **Визуальный синтаксис** («исчисление фигур»):
   - алфавит фигур (таблица с рисунками);
   - 17 заготовок;
   - операции: ввести фигуру, добавить пункт, добавить сторону или столбец, добавить зону, добавить связь, вложить;
   - таблица ALLOW (валентные места);
   - обязательные части (критические места);
   - запреты: пересечение линий, линия вверх, второй родитель, пустая фигура;
   - мягкие пределы.
4. **Соответствие «строка текста → операция»** (одна таблица). Тот, кто знает таблицу, знает весь язык.
5. **Правила раскладки** (раздел 4 ниже) и каталог подсказок.
6. **Определение правильного конспекта** (аналог тезисов 36–37) и **корпус примеров** как приёмочные тесты.

## 4. Три правила из главы 32, которые берём в ГРАФ

### 4.1. Равная ширина в ряду и колонке (§ 12)

Паронджанов: ширина всех икон ветки одинакова, по умолчанию её задаёт конструктор, пользователь может изменить. Для нас:
- фигуры одного ряда (Линейка, стороны Очной ставки) и одной колонки (столбец Шеренги, Ступени) получают **одну ширину** — по самой широкой, в пределах `ширина:`;
- разные ряды и колонки могут быть разной ширины.

Многое уже так работает, но в грамматике это должно стать **правилом**, а не свойством текущего движка.

### 4.2. Структуризация текста внутри фигуры (§ 13–14)

Правило Паронджанова для Комментария почти дословно совпадает с нашей разметкой внутри фигуры:

| Паронджанов | ГРАФ |
|---|---|
| Первая часть без маркера — заголовок | Первая строка фигуры без `-` — подзаголовок фигуры |
| Остальные части начинаются с маркера ● | Строки `- пункт` |
| Части разделены отбивками; отбивок на одну больше, чем частей | Отбивка между **многострочными** пунктами и по краям фигуры |
| Однострочные абзацы отбивками не разделяются, перед маркером отступ | Подряд идущие **однострочные** пункты стоят плотно, с отступом маркера |

Правило отбивок предлагаю записать в раздел «Правила раскладки» как обязательное.

### 4.3. Два режима ДРАКОН-схемы (§ 14)

Если нужна «просто картинка», в Действии разрешён свободный словесный текст. Если нужна трансляция в код, требования строже. Для ДРАКОН-модуля:
- **режим «схема»** — свободный текст, работают только подсказки по стилю: повелительное наклонение, длина, «и/или» в Вопросе;
- **режим «программа»** — операторы в духе Python, проверка переменных, генерация Python, трассировка в Шеренгу.

Режим задаётся строкой настройки (`режим: программа`) и действует так же, как `класс:` в конспекте.

## 5. Требования к текстовому ДРАКОНу (вывод для общей грамматики)

По теореме Паронджанова (т. 36–37) любая правильная схема получается восемью операциями. Чтобы текстовый ДРАКОН мог описать **любую** правильную схему, в нём должна быть запись для каждой из них:

| Операция | Что должно быть в тексте | Нужно в школе |
|---|---|---|
| Ввод атома | Действие, Вопрос, Выбор, цикл, Вставка, Пауза, Вывод/Ввод | да |
| Добавление варианта | ещё один `вариант:` в выборе | да |
| Добавление ветки | `ветка: Имя` | да (силуэт с 7–8 класса) |
| Заземление лианы | `адрес: Имя ветки` внутри развилки (многоадресная ветка) | да |
| Пересадка лианы | переход к точке слияния ниже (выход из середины, аналог `continue` в цикле) | углублённый уровень |
| Боковое присоединение | `параметры:` у Заголовка; синхронизатор | параметры — да, синхронизатор — нет |
| Удаление последней ветки / конца | `без конца` (бесконечный процесс) | нет, резерв |
| Дополнительный вход | второй Заголовок | нет, резерв |

Если какой-то операции нет, часть правильных схем текстом не записать — их можно будет только нарисовать. Сейчас это допустимо, но должно быть сказано в грамматике явно.

## 6. Исправленный лист «Евклид: ДРАКОН и ГРАФ»

Что изменено (файлы прилагаю):
- **Цикл по канону.** Тело цикла стоит на шампуре, вопрос «b = 0?» внизу. Ответ «Нет» уходит вправо, линия поднимается, и вход в цикл идёт горизонтальной стрелкой **влево**: против часовой стрелки, как в «Змее Горыныче» (рис. 79) и в макроиконе «обычный цикл» (рис. 231, 234).
- **Проверка до цикла.** Если b = 0 сразу, лиана обходит цикл справа и сливается с шампуром ниже. Её линия правее линии возврата, пересечений нет. Главный маршрут идёт по шампуру.
- **«Это и есть НОД»** нарисовано иконой **Пояснение**: белая скруглённая рамка справа от иконы, соединённая с ней линией (рис. 20, икона 19). Жёлтую выноску в ДРАКОНе больше не используем.
- Подпись внизу листа обновлена.
